Open ticket 1007766fff · ctext · RFE · filed 2004-08-12

Full verdict

RFE-OPEN, with a working alternative. Keyword classes (addHighlightClass) are matched by exact array lookup, so there is no case-insensitive mode. addHighlightClassForRegexp .t kw blue {(?i)\m(subroutine|function)\M} highlights keywords in any case (verified with Tk 9.1 and 8.6, as aku hinted in 2022).

  • Module ctext · RFE
  • Tested Tk 9.1, 8.6: "Subroutine" and "SUBROUTINE" get the tag through a (?i) regexp class but not through a keyword class.
  • Cause ctext.tcl:ctext::addHighlightClass / highlight look up words case-sensitively.
  • Prototype none for an option (that would be an API addition). The (?i) workaround is documented in 1007764fff.patch.
  • Suggested ticket action Use a regexp class with the (?i) embedded option, e.g. {(?i)\m(subroutine|function)\M}, now mentioned in the docs. Close as Works For Me unless a real -nocase option for keyword classes is still wanted.
