Triage run 2026-11-15

all 509 open and Pending tickets of tcllib: 308 bugs, 150 feature requests and 51 patches, many from the SourceForge era. They were checked in 26 batches on Linux against tcllib trunk (adeef82ca0, 2026-11-13) with Tcl 9.1, 9.0, 8.6 and 8.5. Network modules (ftp, ftpd, smtp, pop3, pop3d, dns, ldap, http, websocket, …) were tested against local servers on 127.0.0.1. A Windows 11 VM ran the Windows-only tickets and the whole test suite. 148 prototype patches were written. Every patch that changes code includes a regression test, which fails without the fix and passes with it on 9.1 and 8.6. Nothing has been committed or posted yet.

Progress (2026-11-16)

35 fix branches are on the server for 40 tickets, each with a "Proposed fix in branch" comment on its ticket. The emoji in the rows show each ticket's state. The branches are the prototypes with their regression tests. The module tests pass on Linux with Tcl 9.1, 8.6 and 8.5, and on Windows with 9.1 and 8.6, with no failure that trunk does not have too.

  • The Windows runs found that two new tests needed changes, made on their branches: tar-tkt-🔧7446477f89 needs paths longer than Windows' MAX_PATH, so it now runs on Unix only; practcl-snapshot-unpack-001 could not delete an archive that ScmUnpack leaves open, so the test now closes it.
  • The 8.5 run found that mime cannot be loaded on 8.5, although it declares 8.5 support: tcl::chan::memchan and about 20 other virtchannel files use try since 14c9a08008 (2024-09-20, in tcllib 2.0).
  • Left out for now, because the prototypes change behaviour: ⬜1606391fff (htmlparse script/style text), ⬜1743868fff (pop3d TOP line counting), ⬜2526629fff (SPF with several records), and the decisions listed below.

Broken on trunk or in the last release (worth fixing first)

  • 🔧61e49798ee: package require nettool always fails. Since 94a3829047 (2024-09-13, in tcllib 2.0) its pkgIndex.tcl names nexttool.tcl. The same check found four more index entries that don't match the code (🔧523f7e0556). Among them is rest: the index says 1.7 while rest.tcl provides 1.8, so package require rest fails on trunk (🔧cdbdd399e4).
  • 🔧af927e957f: ldap::starttls and ldap::info whoami always fail with "invalid command name" in tcllib 1.21, 2.0 and trunk. The 2022 change 495ba2b8f5 calls asnEncodeString, which asn does not export.
  • 🔧3308105fff: since tcllib 1.21 (1df85e69fb), when the server rejects a message, smtp::sendmessage returns code 7 with a raw dict instead of raising an error. A rejected Bcc copy is not reported at all.
  • Tcl 9:
    • 🔧29ff5c3abd: autoproxy::tls_socket uses the wrong host;
    • 🔧34a589f660: ftpd does not load;

  • 🔧0f65bfa2d3: struct::graph::op::tarjan hangs for node names with spaces. This is a regression of Bug 2815302: the 2009 fix was undone by the GSoC merge 42c21b6c75.
  • 🔧2848168fff, confirmed on Windows: ::crc::Crc gives a wrong CRC for non-reflected 32-bit CRCs, because tcl_platform(wordSize) is 4 there.
  • 🔧7bd2d439ca: with tcllibc, crc32 of files over 4 KiB fails on Tcl 9 on Windows (emulated on Linux).

Test suite problems found

  • websocket.test uses the external echo server ws.ifelse.io and has no constraint, so a full sak test run contacts an outside host. It needs a local server (the triage used one) or a constraint that is off by default.
  • On Tcl 9.x, without any patch:
    • crc: 7 failures, because the tests expect the old wording of the "expected byte sequence" error (Update 11-21: reported in 3c4d01349d);
    • hook: 2 failures on 9.1 (-errorstack);
    • snit 1: 27 failures on 9.1 (3 on 8.6), because snit::typemethod/method at runtime now need a fully qualified type name.
  • doctools msgcat-2.0 fails in any non-C locale (Update 11-21: reported in 3c4d01349d, together with mime-14.0 below and tepam's Tk tests). Under 8.6 in a non-UTF-8 locale, mime, textutil, base64 and yaml fail too (⬜509776ffff has a fix).
  • mime.test leaves checkmime.msg in the current directory, and practcl.test leaves an empty test directory.
  • httpd.test, jpeg.test and tiff.test only run through sak, because they don't load their own dependencies.
  • New test files were added for modules that had none: ftp, ftpd, rest, smtp, term, nmea, imap4, generator, pluginmgr, coroutine, coroutine::auto. (Update 11-21: these modules now also have full test suites on their tests-* branches.)
