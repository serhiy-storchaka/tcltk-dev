⬜1537469fff2006"make install" fails on cygwinNEEDS-WINDOWS (Cygwin). Probably still present, judging from the code.

Open ticket 1537469fff · Bug · Installation · filed 2006-08-09

Full verdict

NEEDS-WINDOWS (Cygwin). Probably still present, judging from the code.

  • Module build system (configure.ac, Makefile.in, installer.tcl)
  • Tested code read only. configure.ac sets CYGPATH="cygpath -w" for every *CYGWIN_NT* host, regardless of whether the tclsh is a Windows-native build or Cygwin's own (Unix-platform) Tcl. The 2014 log shows the result: Cygwin's tclsh8.5 gets C:\Users\...\lib\tcllib1.16, treats it as a single relative path component, and file mkdir fails with "no such file or directory".
  • Cause configure.ac:4-11 chooses CYGPATH by uname -s instead of by the Tcl platform. With Cygwin's Unix-built Tcl, CYGPATH should be echo.
  • Prototype none. The fix belongs in configure.ac (plus regenerated configure) and needs Cygwin to verify. A regression test is impossible in the Tcl testsuite.
  • Suggested action keep open. Test on Cygwin with ./configure && make install. Fix by making CYGPATH echo when $TCLSH_PROG reports tcl_platform(platform) eq "unix".
  • Suggested ticket comment The 2014 log shows Windows paths (cygpath -w) handed to Cygwin's Unix-built tclsh, which cannot use them. configure.ac still picks cygpath -w for every Cygwin host. It should depend on the tclsh's platform instead.
